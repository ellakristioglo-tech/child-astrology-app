# Data-subject request and authority-dispute procedure

Version: 13 September 2026

1. Receive requests at ellakristioglo@gmail.com and record date, scope and requester role without copying unnecessary child data.
2. Explain that child profiles and personalised app content are only on the requester's device and cannot be retrieved by the operator; Supabase holds the adult account e-mail/user ID and authentication metadata.
3. Direct the requester to Settings for export, history deletion, Delete Child, or Delete Account and Data. The latter must delete the Supabase account before erasing local data.
4. For a child aged 16+ in the Netherlands, accept a direct request and verify identity proportionately. Do not require excessive identity documents by default.
5. If authority is disputed, instruct the current user to stop using and delete the profile while the dispute is assessed. Do not create a cloud copy “for evidence”.
6. Respond within the applicable GDPR period, document any extension/refusal and explain the right to complain to Autoriteit Persoonsgegevens.
7. If Supabase account data or any external analytics identifier is relevant, verify identity proportionately and action the request with the relevant processor where legally required.
8. Record closure and delete support copies when no longer necessary.

If in-app Supabase deletion fails, keep the local data/session available for retry, log no child content, and offer `ellakristioglo@gmail.com` as the manual deletion route. Update this procedure before adding support tooling, cloud child storage or any new account-linked data.
